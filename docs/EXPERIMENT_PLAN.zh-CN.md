# 共享末端深度控制的实验计划

版本：v2.1，2026-10-11。状态：RTX 5080 先导已完成，判定不放行，正式实验未开始；结果见[先导报告](PILOT_REPORT.v2.1.zh-CN.md)。v2 替换 v1；v2.1 只修订第 3.4 节的 BF16 等价门槛。修订内容见第 11 节。数学推导见[数学审计](MATHEMATICAL_AUDIT.zh-CN.md)，固定参数见[协议配置](EXPERIMENT_CONFIG.v2.json)，CPU 代数自检见[检查结果](EXPERIMENT_MATH_CHECK.v2.json)。

## 1. 研究问题

### 1.1 要检验的机制

语言模型的末端表示同时承担两件事：预测下一个词，以及决定后续计算投入多少。把这两件事放进同一组参数联合训练后，模型用同一段前向得到的表示选择循环深度。本实验在一个已经学会循环计算的模型上检验这个机制，这样"学会循环计算"和"学会决定循环次数"可以分开验证。

实验对象是 Huginn-0125，一个由马里兰大学 tomg-group 发布的循环深度语言模型（recurrent-depth language model）。它的循环核心保持冻结；训练对象是共享的两层末端低秩适配器（Low-Rank Adaptation，LoRA）与一个四维深度读出。同一套 LoRA 参数既影响下一词分布，也影响深度选择。主任务是通用语言建模，评价指标是连续文本后缀的逐 token 负对数似然（Negative Log-Likelihood，NLL），单位 nat。

### 1.2 两个研究问题

本实验设一个主问题和一个次问题，分别检验、分别报告。

1. 主问题。在相同推理计算预算下，共享生成与深度控制的模型 E，是否优于由同等适配的固定深度模型与输入无关深度混合构成的参照策略 R。预期方向是 E 优于 R。
2. 次问题。用 Jev 式采样梯度训练的模型 J，与用精确期望梯度训练的模型 E，在相同信息、模型、辅助损失和训练机会下，质量是否有差异。预期是两者没有差异；若有差异，E 略优。

次问题的预期方向来自数学审计第 4.3 节：对线性动作成本，J 的梯度估计是 E 的精确梯度加上零均值采样噪声，采样本身没有增加任何关于动作结果的信息。因此次问题是一项双侧检验，它回答"采样噪声是否损害训练"，并同时报告在实际样本量下能检出的最小差异。确认集规模只由主问题决定。

"Jev 式"指 [Canopy-Jev](https://github.com/Camellia86/Canopy-Jev) 固定版本 `b71f97b` 的 `docs/TRAINING.md` 公开的训练配方：用 Dirichlet 分布的真实样本做留一法（leave-one-out）策略梯度估计，每个状态 16 或 64 个样本，辅助损失为 0.1 倍交叉熵（cross-entropy，CE）、0.01 倍 Brier 分数和 0.1 倍对固定参考分布的 KL 散度。该文档没有公开温度、探索质量和 Dirichlet 概率变换的数值。本协议沿用上述结构、64 个样本和三个辅助系数；浓度 $\kappa$、平滑 $\varepsilon,\eta$、软标签温度 $\tau$ 和四个动作是本协议自己的选择，第 4.2 节逐一给出。

### 1.3 本实验与仓库其他内容的关系

本仓库的其他文档和 `src/jev_routing` 代码描述另一条路线：外部 Canopy-Jev 27B 决策模型读取完整合法上下文、专家能力卡和执行回执，为每个 token 做专家与深度的联合决策。本实验与那条路线共用"用数值决策分配计算"的研究目标，但在三个方面不同，解读结论时要记住这三处差异。

- 控制器是模型自身的末端表示加一个线性读出，没有外部教师模型。
- 动作只有循环深度，没有专家选择。
- 每个请求只在前缀末端决策一次，128 个输出 token 共用这个深度。

本实验回答的是：一个模型自己的末端表示，在计入全部控制开销后，能否以同一份前向同时完成生成与深度分配，并在相同预算下改善语言质量。专家路由和 Canopy 权重迁移属于其他协议。实验代码独立于 `src/jev_routing` 和 Canopy-Jev。

### 1.4 原始设想与本实验的对应

原始设想来自 Canopy-Jev 的 27B 结构：Qwen3.8-27B 基座的前 60 层冻结并同时用于生成和循环，第 60 到 63 层的副本带 LoRA 承担决策，决策分支在读完输入后选择循环次数。把一个普通 27B 网络的某一段改成可重复调用的模块，需要另外定义状态注入、层索引、位置编码、循环训练分布和训练语料。本实验先在已经具备循环能力的 Huginn 上检验共享末端能否同时承担生成与深度决策；这一步成立之后，再讨论向 27B 结构迁移。原始设想在本实验中对应三个模块：共享的前置层与循环核心、共享的末端两层、四维深度读出。

## 2. 模型

### 2.1 固定版本与结构

采用 [Huginn-0125 固定版本](https://huggingface.co/tomg-group-umd/huginn-0125/tree/bb6621b65e90b6a4b9b29ef88dc83866d450470c) `bb6621b`。按该版本的 `config.json`：

| 项目 | 值 |
|---|---:|
| 前置模块层数 | 2 |
| 循环核心层数 | 4 |
| 末端模块层数 | 2 |
| 隐藏宽度 $h$ | 5,280 |
| 前馈宽度 $m$ | 17,920 |
| 词表大小 | 65,536 |
| 注意力头 | 55 头 × 96 维 |
| 词嵌入与输出头 | 绑定（tie_embeddings） |
| 独立参数总数 | 3,564,976,800 |
| 训练时平均循环次数 mean_recurrence | 32 |
| 训练时循环次数采样 sampling_scheme | poisson-lognormal-filling |

参数总数按融合矩阵、全部归一化向量、q/k 偏置和绑定词嵌入逐项相加得到，BF16 权重约 6.64 GiB。模型卡写明"The model is trained to accept an arbitrary number of steps"，"using fewer than 4 steps will result in very coarse answers"，以及给足上下文时"benchmarks show the model improving up to around num_steps=64"。

### 2.2 候选深度

深度的单位是执行整个四层循环核心一次。动作集合为

$$
\mathcal D=\{4,8,16,32\}.
$$

四个值的依据：4 是模型卡给出的最低可用步数；32 是训练时的平均循环次数；8 和 16 按几何间隔填充。64 虽然仍有收益，但按展开层数估算成本约为深度 16 的 3.8 倍，超出本实验的预算刻度，不纳入候选。

## 3. 一次请求的定义

### 3.1 输入、动作与预测位置

每个样本是一个 256 个 token 的窗口 $u_0,\ldots,u_{255}$，其中 $u_0$ 是起始符 BOS，其余是正文。前缀为 $x=u_{0:127}$，共 128 个位置；目标为 $y=u_{128:255}$，共 128 个 token。位置从 0 开始计数。

教师强制（teacher forcing，把真实后缀作为输入）评价的输入是 $u_{0:254}$，共 255 个位置。损失只取位置 127 到 254 的 128 个输出，它们分别预测 $u_{128}$ 到 $u_{255}$。最后一个目标 $u_{255}$ 不作为输入。控制器的输入始终是独立的 128 个前缀位置 $u_{0:127}$，读取位置 127 的末端表示。

每个请求只在前缀末端选择一次深度，之后 128 个输出 token 共用这个深度。这个粒度直接回答"读完输入后决定投入多少计算"，并避免多次决策带来的状态分布漂移问题。Huginn 模型卡展示的逐 token 可变计算是零样本能力，模型没有为它训练过；逐 token 决策属于另一项协议。

### 3.2 共享执行顺序

1. 对整个前缀运行前置模块和 4 次循环，保留前置表示、未经最终归一化的原始循环状态、循环计数、绝对位置和逐层键值缓存（key-value cache，KV 缓存）。
2. 对整个前缀运行共享的末端两层。取最终归一化之后、语言建模头之前的位置 127 表示，经固定读出 $(W_0,b_0)$ 得到四个深度的概率。
3. 选择 $D=4$ 时，复用这次末端结果及末端 KV。选择 $D>4$ 时，把整个前缀从原始循环状态继续到深度 $D$，再对整个前缀运行同一末端模块；丢弃深度 4 的末端 KV，以深度 $D$ 的末端 KV 开始生成。
4. 以深度 $D$ 自回归生成 128 个 token；每个新位置使用与同深度原生模型一致的循环层 KV。

"整个前缀补算"是固定的执行语义。只对前缀末位置加深会让它读取其他前缀位置的浅层状态，那是另一种模型。

### 3.3 实现约束

本节面向实现者，引用 Huginn 固定版本的源码标识符；数学审计第 8 节列出对应行号。

- `iterate_forward` 的返回值已经过 `ln_f` 归一化，`latent_states` 也已归一化。续算必须使用 `iterate_one_step` 或等价核心调用产生的原始状态。
- 末端特征缓存保存恰好归一化一次、作为末端输入的表示，并带类型标记，避免重复归一化。
- 深度 4 到 $D$ 的续算必须保持 `block_idx` 和 `current_step`，并使用逐循环层独立的 KV 策略。固定 `cache_lookup_strategy="full"`、`continuous_compute=False`、`test_time_noise=0`。
- 四轮断点对应 `block_idx=17`、下一轮 `current_step=4`、`_seen_tokens=128`。
- 末端层用负层索引写 KV。补算后重建完整前缀的末端 KV。原生缓存更新器把送入的位置当作序列尾部窗口写入；本协议总是送入完整前缀，避免对非尾部子集的错位写入。
- 前缀控制路径和整段教师强制路径对同一位置 $t$ 必须传入同一绝对位置的旋转位置编码（RoPE）索引；位置索引由调用方按绝对位置显式传入。
- KV 缓存按实际最大长度 255 动态分配，禁止按 4,096 位置为全部深度预分配。
- 生成调用与控制调用必须引用同一个 LoRA 参数对象。

### 3.4 等价性检查与阈值

先导的技术检查包含三项一致性测试：

1. 相同前缀配不同后缀时，控制表示和四个动作概率逐位一致。
2. 同一初始状态下，先 4 轮再续 $D-4$ 轮，与一次运行 $D$ 轮，目标概率与 NLL 一致。
3. 255 位置教师强制，与逐 token 增量缓存运行，目标概率与 NLL 一致。

FP32 门槛检验实现是否正确，在 CPU 上用 8 个前缀 token、8 个目标 token、深度 4 与 8 运行：

| 比较 | 概率最大绝对误差 | 每 token NLL 误差 |
|---|---:|---:|
| 教师强制 vs 增量缓存 | $\le 10^{-5}$ | $\le 10^{-4}$ |
| 先 4 轮再续 vs 一次运行 $D$ 轮 | $\le 10^{-5}$ | $\le 10^{-4}$ |

BF16 门槛检验协议精度下是否存在系统偏差，在 GPU 上用完整的 128 + 128 窗口运行：

1. 先 4 轮再续与一次运行 $D$ 轮的增量路径，四个深度上目标 logits 逐位一致。
2. 取先导训练集前 64 篇、四个深度，记 $\Delta_{i,d}$ 为文档 $i$ 在深度 $d$ 下增量路径减教师强制路径的平均 NLL，$\Delta_i=\frac14\sum_d\Delta_{i,d}$。要求 $|\bar\Delta|\le0.0005$ 且 $\bar\Delta$ 的 95% 正态区间含零。
3. 每个深度 $|\bar\Delta_{\cdot,d}|\le0.001$，防止不同深度的偏差方向相反、在合并时相互抵消。

每文档差的标准差与最大绝对值同时报告。BF16 下两条路径的矩阵形状不同（255 行整段计算与逐 token 计算），累加顺序不同，舍入误差在最多 132 层展开中累积，每文档平均 NLL 的差约有 0.0025 的标准差，方向随机。本协议所有质量比较都在同一条教师强制路径上、对至少 512 篇文档取平均，这种噪声在平均后约为 $10^{-4}$；需要排除的是系统偏差，第 6.6 节的配对效应偏差检查在确认集上再核一次。

超过阈值即定位实现问题；阈值在正式实验前固定，不以放宽阈值继续。舍入误差附近的硬路由分歧单独记录，主评价使用概率期望，不受其影响。

## 4. 参数、训练信号与实验臂

### 4.1 共享参数

冻结词嵌入、前置模块、循环核心、所有基础权重和语言建模头。两个末端层的 `attn.Wqkv`（$h\to3h$）、`attn.proj`（$h\to h$）、`mlp.fc`（$h\to2m$）、`mlp.proj`（$m\to h$）各插入 rank 8、alpha 16、dropout 0 的 LoRA，共 1,536,000 个可训练参数。

LoRA 的两个低秩因子记为 $A_{\rm lora}\in\mathbb R^{8\times d_{\rm in}}$ 和 $B_{\rm lora}\in\mathbb R^{d_{\rm out}\times 8}$，增量为 $\Delta W=2\,B_{\rm lora}A_{\rm lora}$。$A_{\rm lora}$ 按 PEFT 默认的 Kaiming 均匀分布初始化，即 $\mathcal U(-1/\sqrt{d_{\rm in}},\,1/\sqrt{d_{\rm in}})$，生成器种子为训练种子；$B_{\rm lora}$ 初始化为零。第一步 $A_{\rm lora}$ 的梯度为零而 $B_{\rm lora}$ 有梯度属于预期；两者同时为零会使两者都无法学习，检查程序须区分这两种情况。参数主副本为 FP32。

部署时 LoRA 增量合并进基础矩阵，推理 FLOPs（浮点运算次数）与冻结模型相同。训练 FLOPs 单独记账。

读出 $W_0\in\mathbb R^{4\times5280}$、$b_0\in\mathbb R^4$ 在独立的预热集上训练（第 5.7 节），之后在所有训练臂中冻结。LoRA 为零时读出在每个训练样本上的分布 $\mu_{\rm ref}$ 在训练前保存为固定参考。

### 4.2 成本与控制分布

对样本 $i$ 和当前参数 $\theta$，深度 $d$ 的逐 token 平均 NLL 为

$$
\ell_{i,\theta}(d)=-\frac1{128}\sum_{j=128}^{255}\log P_\theta(u_j\mid u_{<j};d),
$$

动作成本为

$$
c_{i,\theta}(d)=\ell_{i,\theta}(d)+\lambda f(d),
$$

其中 $f(d)$ 是包含控制开销的归一化推理 FLOPs（第 6.1 节），$\lambda$ 由先导按第 7.3 节的规则固定。训练时计算四个动作的当前 NLL。冻结核心的特征可以缓存；共享末端持续更新，因此动作 NLL 和软标签都必须随参数重算。

控制概率 $p=\operatorname{softmax}(W_0 z_\theta+b_0)$，其中 $z_\theta$ 是位置 127 的末端表示。Dirichlet 参数与其均值为

$$
\alpha_d=\kappa\left[(1-\varepsilon)p_d+\frac{\varepsilon}{4}\right]+\eta,\qquad
\mu_d=\frac{\alpha_d}{\sum_k\alpha_k},\qquad
\kappa=256,\ \varepsilon=0.01,\ \eta=0.001.
$$

数学审计第 2.1 节给出 $\mu_d=\beta p_d+(1-\beta)/4$，$\beta=\kappa(1-\varepsilon)/(\kappa+4\eta)$。

共同辅助项用当前成本生成停止梯度的软标签 $s=\operatorname{softmax}(-\operatorname{sg}(c)/\tau)$，$\tau=0.05$：

$$
\mathcal A_\theta=0.1\,\operatorname{CE}(s,\mu)+0.01\sum_d(\mu_d-s_d)^2+0.1\,\operatorname{KL}(\mu\,\Vert\,\mu_{\rm ref}).
$$

E 与 J 使用同样的标签重算与停止梯度规则。

### 4.3 四个训练臂与四个免训练对照

| 臂 | 生成梯度 | 路由梯度 | 用途 |
|---|---|---|---|
| E | $\sum_d\operatorname{sg}(\mu_d)\nabla\ell_d$ | 精确 $\sum_d c_d\nabla\mu_d$，加辅助项 | 主方法 |
| J | 同 E | 64 个 Dirichlet 样本、留一基线的 score 函数梯度，加辅助项 | 次问题 |
| F16-A | $\nabla\ell_{16}$ | 无 | 单深度末端适配参照 |
| FMIX-A | $\tfrac14\sum_d\nabla\ell_d$ | 无 | 多深度末端适配参照 |

E 与 J 的差别严格限制为路由梯度的估计方式；生成梯度和辅助项完全相同。F16-A、FMIX-A 使用相同的 LoRA 位置、参数量、训练文档、优化器和更新次数。FMIX-A 的训练权重固定为均匀，保证每个深度都获得语言建模梯度；它的部署混合在正式校准集上选择。

免训练对照共四组，与训练臂共用样本、分词、初始状态和精度：

- 冻结模型的深度 4、8、16、32。
- 预热读出加零 LoRA 的控制器，用来度量共享表示训练新增了多少收益。
- E-static：对 E 的最终检查点关闭输入相关路由，在校准集上选固定深度混合。它进入参照策略 R 的候选池。
- J-static：同样处理 J 的检查点，仅作机制分析。

### 4.4 梯度实现

一次更新按以下顺序执行，整个过程只在最后更新一次参数。

1. 无梯度计算前缀控制路径，得到 $\mu$。
2. 依次对四个动作运行末端与语言建模头，按停止梯度的 $\mu_d$ 加权反向，记录每个动作的当前成本 $c_d$。
3. 重新运行前缀控制路径，累积 E 的精确路由梯度或 J 的采样路由梯度，以及辅助项梯度。
4. 优化器更新。

生成分支的代理损失只含 NLL，因为 $\lambda f(d)$ 与参数无关。两类分支的代理标量不能相加当作目标值；日志单独记录真实目标 $\sum_d\mu_d c_d+\mathcal A_\theta$。数学审计第 3.3 节证明两类代理的梯度之和等于联合目标的梯度。

J 的采样代理中，样本 $q$、样本成本 $v_m$ 和留一基线 $b_m$ 全部停止梯度；只让对数密度对参数求导。数学审计第 4.2 节说明让 $q$ 的梯度穿过对数密度会引入额外项。

### 4.5 训练规程

| 项目 | 值 |
|---|---|
| 正式训练文档 | 4,096 篇，2 个 epoch |
| 微批量 / 有效批量 | 1 / 8 |
| 每臂每种子更新次数 | 1,024 |
| 训练种子 | 17、29、43、61 |
| 优化器 | AdamW，学习率 $10^{-4}$，weight decay 0.01，梯度范数裁剪 1 |
| 学习率调度 | 5% 更新线性预热，随后 cosine 衰减至 $10^{-5}$ |
| 精度 | BF16 前向；FP32 参数主副本与损失；Dirichlet 概率运算 FP64 |
| 主检查点 | 最终更新 |

四臂四种子共 16 次训练、16,384 次更新。25%、50%、75%、100% 的训练曲线用于诊断。正式配置固定后不以筛选集或确认集选择检查点。各臂的实际训练 FLOPs、GPU 小时和读取字节数同时报告。

训练集每篇文档只重复两次。路由监督 $c_\theta(d)$ 只在训练文档上重算，重复次数越多，训练文档被记忆后四个深度的成本差越小，软标签越接近均匀或噪声；这个效应只作用于 E、J，不作用于没有路由项的 F16-A、FMIX-A。两个 epoch 是在特征缓存容量和这一不对称之间的折中。训练过程中在预热集上监控路由软标签与留出成本排序的一致性，作为诊断。

## 5. 数据

### 5.1 来源与行号

数据固定为 [SmolLM-Corpus](https://huggingface.co/datasets/HuggingFaceTB/smollm-corpus/tree/3ba9d605774198c5868892d7a8deda78031a781f) 固定版本 `3ba9d605` 的 `fineweb-edu-dedup/train-00000-of-00234.parquet`。文件长度 2,395,121,191 字节，SHA256 为 `220d0c36f13f24046f080dcd9a9339862d6a0e43f214dd430ed20552c265e309`，共 812,684 行。

源行号 $r$ 定义为用 pyarrow 按文件内 row group 顺序顺次读取时该行的 0 基序号。清单同时记录该行的 `id` 列，供第三方核对自己读到的第 $r$ 行。

本协议只使用行号 24,096 到 199,999。此前的本地实验（[成熟 MoR 六臂实验](https://github.com/zhangtt5885/loopjev/blob/f6af2a9d12d33fae748b80427971e5011f906b2c/docs/mor-six-arm-v1.zh-CN.md)与 [Huginn 逐题深度探针](https://github.com/zhangtt5885/loopjev/blob/f6af2a9d12d33fae748b80427971e5011f906b2c/docs/huginn-depth-probe-v1.zh-CN.md)）使用了该分片的行 0 到 24,095，行号偏移使本协议的文档与那些实验不重叠。本协议所有模型都从冻结的 Huginn 与零 LoRA 开始，那些实验的产物不进入本协议，因此只需行号偏移，无需额外排除历史哈希。

### 5.2 规范化、去重与切分

规范化函数 $N(\text{text})$ 定义为：

1. 用 Python 3.12 的 `unicodedata.normalize("NFKC", text)` 做 NFKC 规范化（Unicode 15.0）。
2. 按 `str.isspace()` 判定的空白切分，再用单个 U+0020 连接，即 `" ".join(s.split())`；该步骤同时去掉首尾空白。
3. 不做大小写折叠。

三个哈希的定义：

| 名称 | 定义 |
|---|---|
| 去重键 | $\mathrm{SHA256}(\mathrm{UTF8}(N(\text{text})))$ |
| 切分桶 | $\mathrm{SHA256}(\mathrm{UTF8}(\text{"jev-shared-v2"})\,\Vert\,\mathrm{0x00}\,\Vert\,\mathrm{UTF8}(N(\text{text})))$ 按大端整数对 100 取模 |
| 窗口哈希 | $\mathrm{SHA256}(\mathrm{UTF8}(\text{"jev-window-v2"})\,\Vert\,\mathrm{0x00}\,\Vert\,256\ \text{个 token id 的小端 uint16 拼接})$ |

切分桶与去重键使用同一个 $N$。

数据准备按固定顺序执行：

1. 按行号升序读取 24,096 到 199,999 行的 `text` 字段。
2. 按第 5.3 节分词，判定合格，取 256 个 token 的窗口。
3. 在合格行之间按去重键去重，保留最小行号。
4. 在剩余行之间按窗口哈希去重，保留最小行号。
5. 计算切分桶，按第 5.4 节的表确定角色。
6. 每个角色按行号升序取前若干篇，直到配额满足。
7. 断言所有角色之间窗口哈希交集为空。

任一角色在行 199,999 之前无法满足配额时，停止准备并更新协议版本；不跨桶借用文档。清单保存源行号、`id` 列、原文哈希、去重键、窗口哈希、token 数、桶号和角色，并记录清单文件自身的 SHA256。原始文本不重新分发。

### 5.3 分词与窗口

使用 Huginn 同版本分词器。token 序列为 $[65504]$ 加 `tokenizer.encode(text, add_special_tokens=False, split_special_tokens=True)`，即手工前置 BOS，正文中字面出现的特殊 token 字符串按普通文本切分。文档合格的条件是序列长度至少 256；窗口取前 256 个 token，恰好 256 个合格。窗口内断言不出现任何 id 不小于 65504 的 token，否则剔除并在清单记录原因。

本协议不在窗口内插入 EOS（65505）；EOS 只在解码计时阶段用于"EOS 之后仍按协议长度运行"的规则。微批量 1、序列长度固定为 255 或 128，不使用 pad（65509），注意力掩码为全 1 的因果掩码。

### 5.5 初始循环状态

Huginn 的循环核心以随机初始状态开始。本协议为每个位置显式生成该状态，生成只依赖数据集版本、行号、位置和初始化编号，不依赖文本内容、训练臂或训练种子。全文哈希只用于去重与切分；用它初始化模型会让尚未观察的后缀影响控制器，破坏因果性（数学审计第 1.2 节）。

生成算法如下，所有步骤在 CPU 上执行。

1. 键串为 $\mathrm{UTF8}(\text{"jev-shared-v2-state"})\,\Vert\,\mathrm{0x00}\,\Vert\,\mathrm{UTF8}(\text{数据集 commit})\,\Vert\,\mathrm{0x00}\,\Vert\,\mathrm{UTF8}(r)\,\Vert\,\mathrm{0x00}\,\Vert\,\mathrm{UTF8}(t)\,\Vert\,\mathrm{0x00}\,\Vert\,\mathrm{UTF8}(\rho)$，其中 commit 为 `3ba9d605774198c5868892d7a8deda78031a781f`，$r$ 为源行号、$t\in\{0,\ldots,254\}$ 为位置、$\rho\in\{0,1,2\}$ 为初始化编号，三者均为十进制字符串。
2. 种子为该键串 SHA256 的前 8 字节按大端解释的无符号整数，送入 `torch.Generator(device="cpu").manual_seed`。
3. 建 FP32 向量 $x\in\mathbb R^{5280}$，执行 `x.uniform_(2l-1, 2u-1)`，$l=\Phi(-3)=0.0013498980316301035$，$u=\Phi(3)=0.9986501019683699$。
4. 执行 `x.erfinv_()`，再乘 $\sigma\sqrt2$，$\sigma=0.008703882797784892$，再 `clamp_(-3*sigma, 3*sigma)`。这三步与 `torch.nn.init.trunc_normal_` 的实现逐步相同。
5. 在 FP32 中乘嵌入缩放 $72.66360473632812$（即 FP32 的 $\sqrt{5280}$）。
6. 按最近偶数舍入转为 BF16。

原生实现先 `randn_like` 再在模型精度下做截断正态填充，随机流随张量形状变化。本协议的生成保持相同的截断正态分布，并对所有候选深度、所有臂、所有训练种子使用相同初值；固定深度对照也使用同一初值。主初始化编号为 0；对正式校准集前 128 篇再以编号 1、2 做初始化稳健性评价，计入评价预算，不用于选择检查点。

## 6. 成本、校准与评价

### 6.1 成本账本

设同一检查点关闭控制器后深度 $D$ 的完整请求 FLOPs 为 $F_{\rm native}(D)$，它包含前缀 $D$ 轮循环、后续 127 个输入位置的 $D$ 轮循环、末端和 128 个词表输出。共享控制路径的成本为

$$
F_{\rm plan}(D)=F_{\rm native}(D)+F_{\rm readout}+\mathbf 1\{D>4\}\,F_{\rm coda,prefix}.
$$

选择 $D=4$ 时末端被复用；选择更深时，深度 4 的前缀末端是额外工作，且是整个 128 位置前缀的两层末端。前 4 轮循环属于最终 $D$ 轮，不重复计费。整个请求的循环 token-step 数为 $255D$。

归一化分母是冻结基础模型深度 16 的固定请求 FLOPs：

$$
f(D)=\frac{F_{\rm plan}(D)}{F_{\rm native}(16)},\qquad
f_{\rm static}(D)=\frac{F_{\rm native}(D)}{F_{\rm native}(16)}.
$$

LoRA 已合并，所以 $f$ 只依赖深度与执行形状，对所有臂相同。账本逐项计入前置层、循环注入矩阵、四层核心、两层末端、目标位置语言建模头、路由读出，以及注意力随上下文增长的成本；乘加记作 2 FLOPs，前提固定为单请求 batch 1、128 token 前缀与 128 token 输出。账本由实现后的矩阵形状给出，并用算子剖析器（profiler）核对。所有策略统一执行内核、精度、KV 策略和输出头位置。

### 6.2 参照策略 R

R 在正式校准集上选择。候选池为冻结四深度、F16-A、FMIX-A、E-static 各在四个固定深度下的结果，共 16 个点。每点先平均四个训练种子的 NLL，求成本不超过 1 时 NLL 最小的凸组合；数学审计第 5.3 节证明至多两个支持点即可。并列时依次选择更低成本、更少支持点、按冻结 / F16-A / FMIX-A / E-static 及深度升序更靠前者。四个种子使用同一混合配方，分别代入本种子的检查点。

R 按请求独立抽取一个候选点，与输入无关，不运行控制器。记 R 在校准集上的成本为 $c_R=\sum_d\pi_d f_{\rm static}(d)$，$c_R\le1$。R 低于预算且质量更好时保留其真实成本，不用无用计算填满预算。筛选与确认阶段冻结混合权重，bootstrap 时不重选。

### 6.3 预算校准与同成本规则

主策略按概率抽取一个深度。给定检查点输出的 $\mu$ 和标量 $b$，校准后的策略为

$$
\mu_b(d\mid x)=\frac{\mu(d\mid x)\,e^{-b f(d)}}{\sum_k\mu(k\mid x)\,e^{-b f(k)}}.
$$

E 的 $b_E$ 在正式校准集上用二分法求解，使 E 的平均成本 $\frac1n\sum_i\sum_d\mu_{b}(d\mid x_i)f(d)$ 等于 $c_R$，容差 $10^{-4}$。J 的 $b_J$ 用同一规则求解到同一目标 $c_R$。数学审计第 5.2 节证明平均成本随 $b$ 单调下降。若 $c_R$ 落在可行区间之外，使用可行边界并报告。

同成本规则分两层。

- 校准集上：E 与 J 的平均成本都等于 $c_R$，偏差在 $10^{-4}$ 以内。这一层由校准程序保证，是"同成本"的定义。
- 确认集上：报告 E、J 的实现平均成本及其按文档 bootstrap 的 95% 区间。实现成本落在 $[0.98\,c_R,\,1.02\,c_R]$ 内认定为匹配；高于 $1.02\,c_R$ 时不作同成本结论；低于 $0.98\,c_R$ 时作为更低预算结果报告。任何情形都不在确认集重拟合 $b$。

确认集上的成本是另一组文档上的样本均值，带抽样误差，所以确认集不设 $10^{-4}$ 量级的门槛。

### 6.4 质量评价

质量主结果直接计算 $\sum_d\mu_b(d\mid x)\,\ell(d)$，预算结果计算 $\sum_d\mu_b(d\mid x)f(d)$。两者都是该随机策略的精确条件期望，没有额外的动作采样噪声。R 的质量为各支持点 NLL 的加权期望；它与词表概率混合的 NLL 不同，本协议评价前者（数学审计第 5.3 节）。

硬路由 $\operatorname{argmax}_d[\log\mu(d\mid x)-b f(d)]$ 作独立的次要评价：在同一个正式校准集上单独做一次网格搜索得到它的 $b$，预算与 NLL 按实测报告。随机策略的结论不转写为硬路由结论。

### 6.5 速度评价

速度评价在质量匹配点进行。在成本匹配点 $b_E$，E 比 R 多出读出与前缀末端开销，按构造会更慢。速度问题是：E 把质量降到与 R 相同时，能省多少时间。

1. 速度校准点 $b_{\rm speed}$：在正式校准集上取最大的 $b$，使 E 的期望 NLL 不高于 R 的期望 NLL。E 在 $b_E$ 处若不优于 R，则不存在这样的点，速度评价只报告帕累托曲线。
2. 计时模型：对每个 (检查点, 深度) 组合，强制该深度运行完整计划路径（含控制器与补算），在 16 个计时前缀上各重复 3 次，每组先做 10 次预热，CUDA 同步后计时，得到平均请求时长 $\bar T_s(d)$。R 的支持点同样按原生路径测 $\bar T_{\rm native}$。
3. 期望时长：对确认集前 64 个前缀，E 的期望时长为 $\sum_d\mu_{b_{\rm speed}}(d\mid x_i)\bar T_s(d)$，R 的为 $\sum_d\pi_d\bar T_{\rm native}(d)$。请求形状固定，时长只依赖深度，所以期望时长是精确的。
4. 端到端校验：对每个 E 检查点，按真实采样深度运行 64 个前缀一次，总时长与期望时长之差须在 5% 以内，否则计时模型作废并报告。
5. 速度声明：在 $b_{\rm speed}$ 处，E 的期望时长不高于 R 的 90%，且 E 相对 R 的 NLL 劣化的单侧 95% 上界不超过 0.005 nat。同时报告 $b$ 网格上的 (成本, NLL, 时长) 帕累托曲线。

解码统一为 greedy，固定 128 个输出 token，EOS 之后仍按协议长度运行。记录总时长、首 token 延迟（Time to First Token，TTFT）、输出 token/s、峰值显存和控制器占比。RTX 5080 与 A10 的结果分别报告，不合并。

### 6.6 增量路径复核

同一批 64 个确认前缀，对 E、J 的四个深度和 R 的支持点，用真实增量 KV 路径对固定真实后缀评分，与教师强制评价对照。每项配对效应在两种路径间的偏差绝对值须不超过 0.0002 nat。超过时，质量结论限定于教师强制实现，部署质量判断暂停，待统一增量参考路径完成完整评价后另行报告。

| 先导训练 | 2.5 | 预热读出与 $\lambda$ 规则；E、J、F16-A、FMIX-A 各 64 次更新，种子 17 |
| 筛选与预测 | 2 | 放行判据、诊断量、正式资源预测 |

### 7.2 技术检查

进入先导训练前，以下检查必须全部通过：

- 第 3.4 节三项等价性测试在 FP32 和 BF16 阈值内。
- 生成调用与控制调用引用同一 LoRA 参数对象；首步 $A_{\rm lora}$ 梯度为零、$B_{\rm lora}$ 梯度非零。
- 第 5.5 节的初始状态测试向量逐位复现。
- KV 缓存实际最大长度 255，峰值显存不超过设备的 85%。
- 成本账本与剖析器算子记录一致。

### 7.3 λ 的固定规则

$\lambda$ 网格为 $\{0,\,0.005,\,0.01,\,0.02,\,0.05,\,0.1\}$。每个 $\lambda$ 在预热集上独立训练读出，再计算该读出在预热集上、不加校准（$b=0$）时的平均计划成本 $\bar c(\lambda)=\frac1n\sum_i\sum_d\mu_\lambda(d\mid x_i)f(d)$。选取使 $|\ln\bar c(\lambda)|$ 最小的 $\lambda$，并列取较小者。这样训练目标中的成本权重与部署预算一致，校准标量 $b$ 在预算 1 附近接近零。各 $\lambda$ 的 $\bar c$ 与其读出在先导筛选集上预算 1 下的 NLL 作为诊断报告，不参与选择。

### 7.4 放行判据与诊断

先导训练完成后，在先导校准集上选择静态参照：冻结四深度在成本不超过 1 下的最优混合，成本记为 $c_{\rm static}$。放行判据称为可预测性探针：选定 $\lambda$ 的预热读出加零 LoRA 作为控制器，在先导校准集上校准到 $c_{\rm static}$，在先导筛选集 384 篇上与静态参照做配对比较。

进入正式实验须同时满足：

1. 第 7.2 节技术检查全部通过。
2. 第 8 节的资源预测在正式上限内。
3. 可预测性探针相对静态参照的 NLL 改善，点估计至少 0.002 nat，且按文档 bootstrap 的单侧 95% 下界大于零。

探针未通过时停止本组深度与数据配置，下一版本应改变候选深度、决策粒度或训练范围。先导 E 的结果作为诊断报告，不作为放行依据。

以下诊断量同时报告：

- 事后分配上界：用真实后缀逐文档选深度，在成本不超过 $c_{\rm static}$ 下相对静态参照的改善，用拉格朗日扫描求解，事后动态分配按 $f$ 计费、静态混合按 $f_{\rm static}$ 计费。它是对 4 个带噪声的候选取最小值，正向有偏，只作上界。
- 分半上界：用目标 token 的前 64 个的 NLL 选深度，在后 64 个上评价，去掉选择噪声偏差。
- 先导 E、J、F16-A、FMIX-A 在先导筛选集上相对静态参照的差值、训练梯度范数、实际路由分布。

## 8. 3×A10 正式实验

[A10](https://www.nvidia.com/en-us/data-center/products/a10-gpu/) 为每卡 24 GB GDDR6、600 GB/s 显存带宽。三卡各自独立运行训练任务，16 次训练按臂与种子轮换分配到三卡；单卡可容纳模型与短序列状态，不使用分布式数据并行（Distributed Data Parallel，DDP）。

| 阶段 | GPU 小时上限 | 内容 |
|---|---:|---|
| 正式特征提取与运行环境核验 | 24 | 按文档分片提取，一份公共特征库；100 次代表性联合更新计时 |
| 训练 | 48 | 16 次训练，16,384 次更新 |
| 评价 | 36 | 校准、筛选、确认、硬路由次要评价、初始化复核、增量路径复核 |
| 解码计时 | 24 | 第 6.5 节计时模型与端到端校验 |
| 失败重试与预留 | 12 | 记录用途，禁止悄然增加总预算 |
| 合计 | 144 | 平均每卡 48 GPU 小时 |

48 GPU 小时对应跨臂平均 10.55 秒/更新的上限。正式环境先用先导数据运行 100 次代表性联合更新，测得完整样本提取、训练、评价和解码速度；预测时代入当前数据量、确认集上限 2,048 篇、初始化复核和 20% 波动余量。预测超过任一阶段上限时停止当前协议；减少 epoch、文档、臂或种子的改动都形成新版本。筛选后确认数量锁定时，只能释放先前为上限规模预留的额度。

各卡使用同版本 CUDA、PyTorch、Transformers、注意力实现和编译开关，TF32 关闭。参考软件栈为 Python 3.12.13、PyTorch 2.8.0+cu128、Transformers 4.52.4；仓库内已运行的只有 CPU 代数自检，GPU 环境在先导中首次核验并记录。保存完整包版本与模型代码哈希。GPU 小时通过设备进程运行区间求和。任何阶段达到上限时保存检查点与成本记录。

## 9. 统计检验与结论规则

### 9.1 效应定义

对确认文档 $i$ 和训练种子 $s$，先计算各策略的精确期望 NLL，再对四个种子取平均。正数代表改善：

$$
g_{{\rm arch},i}=\frac14\sum_s\left[\ell_{R,s,i}-\ell_{E,s,i}\right],\qquad
g_{{\rm Jev},i}=\frac14\sum_s\left[\ell_{E,s,i}-\ell_{J,s,i}\right].
$$

### 9.2 主检验与次检验

主检验针对 $g_{\rm arch}$，单侧，$\alpha=0.05$，备择为均值大于零。次检验针对 $g_{\rm Jev}$，双侧，$\alpha=0.05$。两项检验各自报告；只有一项主结论，因此不做家族错误率校正。

检验以文档为配对单位，做 10,000 次 bootstrap（自助法重采样），p 值用零假设下中心化的配对重采样计算。报告原始文档均值、95% 区间、p 值和每个种子的分别结果。

主结论要求同时满足：

1. 第 6.3 节校准集同成本规则成立，确认集实现成本匹配。
2. 主检验显著。
3. 点估计至少 0.005 nat/token。
4. 四个种子各自的平均效应均为正。

四个种子同向在零假设下的概率为 1/16。bootstrap 区间只覆盖文档抽样，不覆盖训练种子的方差；主结论的推断对象是这四个训练实例在同分布新文档上的平均表现，每个种子的配对差及其区间同时列出。

次检验的结论分三类：区间包含零，报告"在可检出范围内未发现采样噪声的损害"并给出可检出效应；区间在零以下，报告"采样噪声损害质量"；区间在零以上，报告该结果并复核，因为它与数学先验不一致。可检出效应按

$$
\Delta_{\min}=\frac{(z_{0.975}+z_{0.8})\,\hat\sigma_{\rm Jev}}{\sqrt n}
$$

计算，$\hat\sigma_{\rm Jev}$ 取确认集上的配对差标准差。

### 9.3 确认集规模

正式筛选集 512 篇只用于估计 $g_{\rm arch}$ 的配对差标准差 $\hat\sigma$，乘 1.2 作为计划标准差 $\sigma$。512 篇上标准差估计的相对标准误约 3%，1.2 倍留出跨桶分布差异的余量。规划效应 $\delta=0.01$ nat，最小实用点估计 $\delta_{\min}=0.005$ nat，功效 0.8，单侧 $\alpha=0.05$：

$$
n\ge\max\left\{
\left[\frac{(z_{0.95}+z_{0.8})\,\sigma}{\delta}\right]^2,
\left[\frac{z_{0.8}\,\sigma}{\delta-\delta_{\min}}\right]^2
\right\},
\qquad z_{0.95}=1.644854,\ z_{0.8}=0.841621.
$$

第一项控制拒绝零效应所需样本量，第二项控制点估计超过实用门槛的概率；数学审计第 7 节说明取较大值即可同时满足两项。结果上取到 128 的倍数，最少 512、最多 2,048。

两个例子：筛选集标准差 0.03 时 $\sigma=0.036$，两项分别需要 81 篇与 37 篇，取下限 512 篇；标准差 0.08 时 $\sigma=0.096$，两项分别需要 570 篇与 262 篇，上取到 640 篇。确认集 512 篇、Jev 配对差标准差 0.03 时，次检验的可检出效应约 0.0037 nat。

若所需样本超过 2,048 篇，运行上限规模并报告功效不足，不把不显著解释为效应不存在。确认集在规模锁定后只运行一次，不根据确认结果扩样。主结果同时提供以确认集标准差计算的可检出效应。

### 9.4 结果对应的研究决策

| 结果 | 支持的判断 | 后续工作 |
|---|---|---|
| 主结论成立 | 在这四个训练实例上，共享末端深度控制在同预算下改善质量 | 扩大语料并复核增益来源 |
| 主结论成立，次检验区间含零 | 采样梯度在可检出范围内无损，精确梯度与采样梯度可互换 | 扩展到分段重复决策 |
| 主结论成立，次检验显示 J 更差 | 应采用精确梯度 | 分析噪声对路由学习的影响 |
| E 与 R 接近，区间上界低于 0.005 | 当前共享末端配置缺乏足够质量收益 | 检查是否需要适配循环核心或改变决策粒度 |
| 区间较宽或成本不匹配 | 当前研究不能完成对应判断 | 报告区间与成本，另立后续协议 |
| 质量通过，速度未通过 | 得到同计算预算下的质量收益 | 优化 KV 与末端重复开销后再测部署收益 |

参数量保持约 3.565B 加 LoRA，本实验不声称压缩模型。事后分配上界、控制器预测准确率与真实 NLL 增益分别报告，前两者不能替代最后一项。

## 11. 相对 v1 的修订

| 修订 | 原因 |
|---|---|
| 同成本门槛移到校准集，E、J 校准到 $c_R$，取代固定目标 1；确认集只报告实现成本与区间 | v1 在确认集上对带抽样误差的样本均值施加 $10^{-4}$ 门槛，而 R 的成本无漂移，门槛会随机或系统性失败 |
| 次问题改为双侧检验，写明预期方向，不参与样本量计算 | v1 以"J 优于 E"做单侧主效应，与审计第 4.3 节的先验矛盾，且以 $\delta=0.002$ 主导确认集规模 |
| 删除 S 臂；种子从 3 个增至 4 个 | S 已含成本软标签，S 与 E 的差别不是"有无策略梯度"；多一个种子改善种子层面的证据 |
| 训练改为 2 epoch × 4,096 篇 | 减少训练文档被记忆后成本差压缩的不对称效应 |
| $\lambda$ 改为预热集上的成本匹配规则 | v1 在 32 篇上按 $10^{-4}$ 并列阈值选 $\lambda$，远小于标准误 |
| 速度评价改为质量匹配点与期望时长模型 | v1 在成本匹配点要求吞吐高 10%，按构造不可达；采样深度计时的抽样误差超过预算带 |
| 放行判据改为可预测性探针，先导筛选集扩到 384 篇、单阶段 | v1 的事后最优判据对噪声没有区分力，64→128 的两阶段规则影响区间覆盖率 |
| 初始状态、规范化、哈希、分词、缓存头给出完整算法与测试向量 | v1 的文字描述不能让两套实现得到相同结果 |

| 预热集增至 1,024 篇并加 weight decay | 读出参数多于样本数，v1 设置会过拟合预热集 |
| LoRA 合并后计成本，次要硬路由评价使用同一校准集 | 适配臂在深度 16 的成本略大于 1 会被线性规划排除；"单独的校准集"没有对应集合 |

| 正式预算改为 24 / 48 / 36 / 24 / 12 | 增量路径复核有了预算归属；计时阶段按带宽估算扩容；训练阶段按 FLOPs 估算缩减 |
