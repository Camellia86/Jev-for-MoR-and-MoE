# 分步深度控制的实验计划 v3

版本：v3，2026-10-12。本版本已被 [v3.1](EXPERIMENT_PLAN.v3.1.zh-CN.md) 取代，第 0 阶段的收益数字作废，原因见 v3.1 第 2.1 节。协议标识 `jev-chunk-depth-v3`。状态：第 0 阶段已完成，只用冻结模型做了测量；训练尚未开始。上一协议的结论见 [v2.1 先导报告](PILOT_REPORT.v2.1.zh-CN.md)，固定参数见[协议配置](EXPERIMENT_CONFIG.v3.json)。第 0 阶段代码在 `experiments/chunk_depth_v3/`，回执在 `results/chunk-depth-v3/`。

## 1. 研究问题

### 1.1 从 v2.1 到 v3

v2.1 先导在通用文本续写上判定不放行。整请求只决策一次、预算等于全用深度 16 的成本时，即使用真实后缀逐文档挑深度，也只比纯深度 16 好 0.0019 nat。复盘先导数据和讨论记录后，得到五条设计原则，v3 逐条落实：

| 原则 | 依据 | v3 的做法 |
|---|---|---|
| 换到深度确有收益的推理任务 | Huginn 论文：多选题在 16 次循环附近饱和，GSM8K 思维链在 32 次循环后仍提升 | 主任务改为 GSM8K 参考解答 |
| 按句子或步骤决策，避开逐 token 决策 | 讨论中提出 chunk 级决策；逐 token 调用控制器会让前向成本成倍增加 | 解答的每一行是一个 chunk，每行开始前决策一次 |
| 决策要读到足够的上下文 | 讨论中提出 Jev 需要足够上下文 | 决策读取题目和已经写出的全部步骤 |
| 控制开销要远小于可分配空间 | v2.1 先导：1.4% 的控制开销造成 0.0024 nat 损失，超过全部空间 | 决策复用上一行最后一个位置已经算出的末端表示，额外计算只有读出 |
| 先测空间再训练，负结果限定适用范围 | v2.1 的教训；讨论中提出负结果往往实验不充分 | 第 0 阶段先测诚实上界和可预测性；参照策略包含按位置编排的深度日程 |

### 1.2 主问题与次问题

本协议设一个主问题和一个次问题。

1. 主问题。在 GSM8K 参考解答上，计算预算取全部步骤用深度 16 的一半。联合训练共享末端与深度读出的控制器 E，在真实执行混合深度的条件下，每 token NLL 能否优于最佳位置日程 R？R 只按"第几步"和"上一步多长"分配深度，与内容无关。预期方向是 E 优于 R。
2. 次问题。用 Jev 式 Dirichlet 采样梯度训练的 J 与 E 的差异。v2 数学审计第 4.3 节证明 J 的梯度是 E 的梯度加零均值噪声，预期两者无差异。本协议只训练一个 J 种子，报告双侧区间，J 不参与样本量规划和主结论。

"Jev 式"的含义与 v2 计划第 1.2 节相同，指 Canopy-Jev 固定版本 `b71f97b` 公开的 Dirichlet 留一策略梯度配方。

### 1.3 适用范围

本实验的结论覆盖以下条件：

- 冻结 Huginn-0125 的循环核心，只训练末端两层 LoRA 与深度读出。
- 输入是 GSM8K 风格、逐行书写的解答。
- 深度在每行开始前选定，按 Huginn 原生的 KV 复用规则执行混合深度。
- 质量用教师强制下的逐 token NLL 衡量，生成正确率作为次要指标。

原始设想中"读完题目决定一次深度"的问题级决策，在第 0 阶段没有诚实的可分配空间，本协议只把它作为诊断量报告。专家路由、以文本候选形式输入的 Jev 读出、ARC 一类带候选答案的任务，留给后续协议。

## 2. 第 0 阶段：可分配空间测量（已完成）

### 2.1 测量设置

- **数据。** GSM8K 固定版本 `740312a` 训练集中，切分哈希桶 0–9 且不超过 320 个 token 的 720 题。这 720 题后续不再使用。
- **格式。** `Question: {问题}\nAnswer: {解答}`，去掉计算器注释 `<<…>>`。
- **chunk。** 题目段为 chunk 0，解答每行一个 chunk。一个 chunk 拥有其 token 所在的位置，它的计分 token 是从这些位置预测出的 token。
- **深度。** 4、6、8、12、16、24、32、48、64，冻结模型、整段教师强制。
- **成本。** 位置 $t$ 在深度 $d$ 下的 FLOPs 沿用 v2 的账本，第 3.4 节给出定义。
- **规模。** 第 0 阶段在 RTX 5080 上用时不到 1 GPU 小时。

### 2.2 深度曲线

去掉 `#### 答案` 这一行之后，冻结模型在 720 题解答上的每 token NLL 与相对成本如下，相对成本以深度 16 为 1：

| 深度 | 4 | 6 | 8 | 12 | 16 | 24 | 32 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 每 token NLL | 1.637 | 1.222 | 0.998 | 0.868 | 0.843 | 0.838 | 0.840 |
| 相对成本 | 0.301 | 0.418 | 0.534 | 0.767 | 1.000 | 1.466 | 1.931 |

深度 48 与 64 相对 32 不再下降。保留答案行的口径下，深度 32、48、64 分别为 1.0035、1.0059、1.0065。

`#### 答案` 这一行的 NLL 随深度大幅上升，深度 6 为 0.652，深度 32 为 3.030。这一行是 GSM8K 特有的格式标记，深层模型对它的预测反而更差，它会扭曲深度比较，所以 v3 从文本中删去这一行。GSM8K 解答的最后一个推理步骤通常已经写出最终数值。

教师强制的解答 NLL 在深度 16 到 24 饱和；论文报告的 GSM8K 准确率在 32 次以后仍提升，那是生成式求解的结果，两者衡量的对象不同。本协议以 NLL 为主指标，以生成正确率为次要指标。

### 2.3 两种决策粒度的上界

下表的增益是相对同预算最佳静态混合的每 token NLL 改善，单位 nat：

| 预算 | 静态参照 | chunk 级，查表 | chunk 级，真实执行 | 问题级，查表 |
|---:|---|---:|---:|---:|
| 0.5 | 深度 6 占 29%、深度 8 占 71% | 0.117 | 0.052 | −0.011 |
| 0.75 | 深度 8 占 7%、深度 12 占 93% | 0.007 | −0.071 | −0.012 |
| 1.0 | 纯深度 16 | −0.021 | −0.103 | −0.007 |

两种上界都用交叉拟合排除选择噪声：

- **chunk 级。** 用每个 chunk 的奇数位计分 token 选深度，在偶数位 token 上评价。"真实执行"一列取最后 96 题，把选出的深度按第 3.2 节的 KV 规则实跑，仍在偶数位 token 上评价。
- **问题级。** 用奇数行选一个全题深度，在偶数行评价，反之亦然。

问题级在所有预算下都是负值：全题统一一个深度的偏好在同一题的不同步骤之间不稳定。chunk 级在预算 0.5 有明显空间，到预算 0.75 以上，混合深度的 KV 代价就超过了收益。

### 2.4 混合深度的 KV 代价

48 题、每个 chunk 随机取深度 4、8、16、32 之一，实跑结果与查表值的差如下，正值表示实跑更差：

| 比较 | 平均差（nat/token） | 标准误 |
|---|---:|---:|
| 随机混合深度，逐题平均 | 0.0475 | 0.0196 |
| 全部深度 16、按 chunk 分段执行，逐题平均 | −0.0001 | 0.0006 |
| 深度高于全部历史 chunk 的 token | 0.129 | 0.026 |
| 其余 token | 0.019 | 0.008 |

按 chunk 分段执行本身不引入偏差。代价集中在"比历史更深"的 chunk 上：历史位置在更深的循环步上没有 KV，按规则只能复用它最后一轮的 KV。查表得到的训练标签不含这项代价，因此主评价必须真实执行，训练标签需要加入代价修正（第 4.2 节）。

### 2.5 只读之前上下文的可预测性

部署时，控制器只能读到某一行开始之前的内容。探针取每行开始前那个位置的末端表示，取自冻结模型深度 8 的运行，然后用岭回归预测该行在各候选深度下的 NLL：

- 按题目分 5 折交叉拟合，正则强度在训练折内部再做一层交叉选择。
- 预算乘子在训练折上校准。
- 位置特征只含"第几行"和"上一行长度"，这两项在决策时已知。

| 预算 | 只用位置 | 只用表示 | 表示加位置 | 只用表示，真实执行 |
|---:|---:|---:|---:|---:|
| 0.4 | 0.0068 | 0.0112 | 0.0108 | 0.0109 |
| 0.5 | 0.0149 | 0.0169 | 0.0166 | 0.0150 |
| 0.6 | 0.0154 | 0.0187 | 0.0187 | 0.0176 |

单位是相对同预算静态混合的每 token NLL 改善。真实执行一列的正则强度按交叉拟合后的查表增益选出，略偏乐观。按逐题平均计算，预算 0.5 时表示读出比位置日程好 0.0040 nat/token，逐题差的标准差为 0.080；预算 0.6 时好 0.0034，标准差 0.067。

三点结论：

1. 只读决策时可得的信息，真实执行仍有约 0.015 nat/token 的收益，约为主效应门槛 0.005 的三倍。
2. 收益的大部分来自位置结构，只用位置的日程就能拿到。
3. 冻结表示在位置之外只多给出约 0.002 到 0.004 nat，低于门槛。本协议要检验的就是联合训练能否把这部分推过门槛。

### 2.6 对设计的约束

1. 决策粒度定为步骤级，问题级只作诊断。
2. 主预算取 0.5，候选深度取 {4, 6, 8, 12, 16}。预算 0.5 下，表示探针选深度 6 和 8 的比例分别为 26% 和 69%，选 24 以上的比例为零。
3. 参照策略必须包含位置日程，否则"动态优于静态"只是在复现日程。
4. 主指标在真实混合深度执行下计算。
5. 训练标签加入"比历史更深"的 KV 代价修正。

## 3. 一次请求的定义

### 3.1 文本与 chunk

文本格式为 `Question: {问题}\nAnswer: {解答}`。解答去掉计算器注释 `<<…>>`，并删去 `#### 答案` 这一行。token 序列为 BOS（65504）加上 `tokenizer.encode(text, add_special_tokens=False, split_special_tokens=True)`，长度不超过 320 个 token 的题目进入实验。

chunk 按 token 最后一个字符的位置归属：

- 落在 `Answer:` 及其之前的 token 属于 chunk 0，即题目段。
- 之后按解答中的换行分行，第 $c$ 行的 token 属于 chunk $c$。

记 chunk $c$ 的位置集合为 $P_c$，它的最后一个位置为 $p_c$。chunk $c$ 的计分 token 是从 $P_c$ 中位置预测出的 token，解答第一行的第一个 token 由 $p_0$ 预测。

题目段固定用深度 16 执行，所有策略相同，它的成本单独报告，不计入预算归一化。决策对象是 chunk $1,\ldots,n$。

### 3.2 执行语义

执行使用 Huginn 的 `HuginnDynamicCache`，查找策略为 `latest-m4`。层索引的约定如下：

- 前置两层的层索引为 0、1，末端两层为 −1、−2。
- 第 $k$ 轮循环的第 $j$ 层（$j=0,\ldots,3$）的层索引为 $s=2+4k+j$。

位置 $q$ 在层索引 $s\ge2$ 上若没有 KV，规则取

$$
s^\star(q,s)=\max\{\,s'\le s:\ s'\ge2,\ s'\equiv s\pmod 4,\ \text{位置 }q\text{ 在 }s'\text{ 上有 KV}\,\}.
$$

同余条件保证复用的是同一个核心层在更早一轮的 KV。前置层和末端层的 KV 对每个位置都存在。

教师强制评价按 chunk 顺序分段预填充：chunk $c$ 的全部位置用深度 $d_c$ 运行，写入层索引 $2,\ldots,1+4d_c$ 的 KV。在实数运算中，这与逐 token 解码的计算图相同；BF16 下的差异按第 7.2 节的偏差门槛检查。

### 3.3 决策时点与控制开销

第 $c$ 行的深度在位置 $p_{c-1}$ 决定。这个位置的末端表示

$$
z_c=\operatorname{ln_f}\big(\operatorname{coda}(\cdot)\big)_{p_{c-1}}
$$

已经在深度 $d_{c-1}$ 下算出，用来预测第 $c$ 行的第一个 token。控制器复用它，读出为

$$
p(\cdot\mid c)=\operatorname{softmax}\big(W_0[z_c;\phi_c]+b_0\big),\qquad
W_0\in\mathbb R^{5\times5290}.
$$

$\phi_c$ 共 10 维：9 维是行序号的 one-hot，序号 1 到 8 各一维，9 及以上合为一维；最后 1 维是上一行长度除以 50。

每次决策的额外计算为

$$
2\times5290\times5=52{,}900\ \text{FLOPs},
$$

而深度 8 下单个位置的计算约为 $3\times10^{10}$ FLOPs，是读出的约 $5.7\times10^{5}$ 倍。v2 中前缀末端的重复计算在 v3 中不存在。

### 3.4 成本账本与预算

位置 $t$ 在深度 $d$ 下的 FLOPs 按逐 token 解码的形状计：

$$
F(t,d)=F_{\rm stack}(1,t+1,d)+F_{\rm head}(1),
$$

$F_{\rm stack}$ 与 $F_{\rm head}$ 的定义同 v2 的成本账本 `experiments/shared_depth_v2/cost.py`。chunk $c$ 在深度 $d$ 下的成本为

$$
f_c(d)=\sum_{t\in P_c}F(t,d).
$$

评价集上一个策略的相对成本为

$$
B(\pi)=\frac{\sum_i\sum_{c\ge1}f_{i,c}(d^\pi_{i,c})}{\sum_i\sum_{c\ge1}f_{i,c}(16)}.
$$

主预算 $B=0.5$，0.4 和 0.6 作为次要预算报告。

## 4. 控制器、训练信号与实验臂

### 4.1 共享参数

LoRA 的位置、秩、缩放、初始化与 v2 计划第 4.1 节相同：两个末端层的四个融合投影，rank 8，alpha 16，共 1,536,000 个参数。生成与控制引用同一组参数对象。

读出 $(W_0,b_0)$ 先在预热集上用冻结模型的表示训练，然后在所有训练臂中冻结。零 LoRA 时读出在每个训练 chunk 上的分布保存为固定参考 $\mu_{\rm ref}$。

### 4.2 chunk 成本与带 KV 代价的标签

对文档 $i$、chunk $c$、深度 $d$，训练用的成本为

$$
C_{i,c}(d)=\sum_{u\in U_{i,c}}\ell_{\theta}(u;d)+\lambda\,n_{i,c}\,r(d)+n_{i,c}\,\kappa\big(d-h_{i,c}\big).
$$

各项含义：

- $U_{i,c}$ 是计分 token 集合，$n_{i,c}=|U_{i,c}|$。
- $\ell_\theta(u;d)$ 是当前参数下、整段深度 $d$ 教师强制得到的 token NLL，每步重算。
- $r(d)=f(d)/f(16)$ 取第 2.2 节的相对成本，依次为 0.301、0.418、0.534、0.767、1.000。
- $h_{i,c}$ 是此前各行所选深度的最大值。
- $\kappa(\Delta)$ 是第 7.3 节在先导中估计的逐 token KV 代价，$\Delta\le0$ 时为零。

训练时，此前各行的深度从当前策略中无梯度采样得到，$h_{i,c}$ 和读出输入 $z_c$ 都取自采样到的上一行深度对应的运行，与部署时的分布一致。

### 4.3 目标函数

每个 chunk 的控制分布沿用 v2 第 4.2 节的 Dirichlet 平滑，动作数 $K=5$：

$$
\alpha_d=\kappa_D\Big[(1-\varepsilon)p_d+\frac{\varepsilon}{5}\Big]+\eta,\qquad
\mu_d=\frac{\alpha_d}{\sum_k\alpha_k},
$$

其中 $\kappa_D=256$，$\varepsilon=0.01$，$\eta=0.001$。

每篇文档的训练目标按计分 token 数 $N_i=\sum_c n_{i,c}$ 归一化：

$$
\mathcal J_i(\theta)=\frac1{N_i}\sum_{c}\sum_d\mu_{c}(d)\,C_{i,c}(d)+\frac1{N_i}\sum_c n_{i,c}\,\mathcal A_{c}.
$$

辅助项 $\mathcal A_c$ 的形式与 v2 相同，为 0.1 倍 CE、0.01 倍 Brier 和 0.1 倍对 $\mu_{\rm ref}$ 的 KL。软标签取

$$
s_c=\operatorname{softmax}\big(-\operatorname{sg}(C_{i,c})/(n_{i,c}\tau)\big),\qquad \tau=0.05,
$$

即按每 token 平均成本取温度。v2 数学审计第 3 节的联合梯度分解与第 4 节的留一无偏性逐 chunk 成立，推导不变。

$\lambda$ 的规则为：网格取 $\{0.25,0.5,1,1.5,2,3\}$，每个 $\lambda$ 在预热集上训练一个读出，选未校准平均相对成本 $\bar B(\lambda)$ 使 $|\ln(\bar B/0.5)|$ 最小者，并列时取较小的 $\lambda$。第 2.2 节的曲线给出这一取值范围的依据：相对成本每增加一个单位，深度 6 到 8 之间的 NLL 下降 1.93 nat，深度 8 到 12 之间下降 0.56 nat，预算 0.5 落在两段之间。

### 4.4 实验臂

| 臂 | 生成梯度 | 路由梯度 | 种子 | 用途 |
|---|---|---|---|---|
| E | $\sum_c\sum_d\operatorname{sg}(\mu_c(d))\nabla\ell(\cdot;d)$ | 精确 $\sum_d C\nabla\mu$，加辅助项 | 17、29、43 | 主方法 |
| J | 同 E | 64 个 Dirichlet 样本的留一 score 梯度，加辅助项 | 17 | 机制分析 |
| SCHED-A | 按冻结位置日程分配的深度上的 $\nabla\ell$ | 无 | 17、29、43 | 末端适配对照 |
| FMIX-A | 五个深度均匀平均的 $\nabla\ell$ | 无 | 17、29、43 | 多深度适配对照 |

SCHED-A 使用的冻结位置日程在预热集上按第 6.1 节的方法求出，训练前固定。

三个免训练对照与训练臂共用数据、初始状态和执行语义：

- **冻结位置日程。** 冻结模型配第 6.1 节的日程。
- **E 的静态日程。** E 的检查点关闭读出，配按它自己的查表结果重新求出的日程。它把联合训练带来的语言建模改进与输入相关路由分开。
- **冻结表示探针。** 按第 2.5 节的方法在正式训练集上拟合岭回归读出。它度量联合训练相对冻结表示的增量。

### 4.5 训练规程

| 项目 | 值 |
|---|---|
| 正式训练文档 | 4,111 篇，2 个 epoch |
| 微批量 / 有效批量 | 1 / 8 |
| 每次训练的更新次数 | 1,028 |
| 训练次数 | 10，共 10,280 次更新 |
| 优化器 | AdamW，学习率 $10^{-4}$，weight decay 0.01，梯度范数裁剪 1 |
| 学习率调度 | 5% 线性预热，cosine 衰减至 $10^{-5}$ |
| 精度 | BF16 前向，FP32 参数主副本与损失，控制分布 FP64 |
| 主检查点 | 最终更新 |

一次更新对每篇文档执行三步：

1. 对五个候选深度各做一次末端加词表头的前向，得到逐 token NLL 和每个位置的末端表示。
2. 无梯度采样各行的上一行深度，取出对应的 $z_c$ 与 $h_{i,c}$，算出成本 $C_{i,c}$。
3. 把生成损失和路由加辅助损失合成一次反向。

读出所需的表示来自第 1 步的同一次前向，不需要额外运行末端。

## 6. 评价

### 6.1 位置日程 R

位置类别由两个因素交叉得到，共 27 类：

- 行序号，取 1 到 8，9 及以上合为一类。
- 上一行长度的三分位，分位点在正式训练集上计算并固定。

对候选池中的每个模型，在正式校准集上用查表 NLL 求解

$$
\min_{\pi}\sum_{k}\sum_d\pi_{k,d}\,L_k(d)\quad\text{s.t.}\quad
\sum_k\sum_d\pi_{k,d}\,F_k(d)\le B\sum_kF_k(16),\qquad \sum_d\pi_{k,d}=1.
$$

其中 $L_k(d)$ 和 $F_k(d)$ 是第 $k$ 类所有 chunk 在深度 $d$ 下的 NLL 总和与成本总和。

这个线性规划有两个约束结构：预算约束一条，每类一条归一化约束。它的极点解至多有一个类别混用两个深度，证明方法与 v2 数学审计第 5.3 节相同。拉格朗日解法对每类取 $\arg\min_d L_k(d)+\nu F_k(d)$，再在边界上随机化。混用的那一类按文档编号的哈希确定性地分配深度。

候选池为冻结模型、SCHED-A、FMIX-A 和 E 的静态日程。三个种子的查表 NLL 先取平均，选出 NLL 最低的池成员和日程，三个种子共用同一配方。R 在校准集上的相对成本记为 $c_R$。

### 6.2 控制器的预算校准

部署策略是确定性的：

$$
d_c=\arg\max_d\big[\log\mu_c(d)-b\,r(d)\big].
$$

标量 $b$ 在正式校准集上用二分法求解，使平均相对成本在 $c_R$ 以下且最接近 $c_R$，偏差不超过 0.5%。校准时的轨迹用查表表示模拟：上一行选定深度后，从该深度的运行中取 $z_c$，不需要真实执行。

确认集上报告真实执行的相对成本。它落在 $[0.98c_R,1.02c_R]$ 内认定为同成本，超出上限时不作同成本结论。

### 6.3 主指标

文档 $i$ 的质量 $\ell_i$ 是决策 chunk 全部计分 token 的平均 NLL，在 BF16 真实混合深度执行下计算。E 与 R 都按各自选出的深度真实执行。

### 6.4 次要指标：生成正确率

取确认集前 512 题，greedy 生成，最多 256 个新 token。题目段用深度 16；模型每输出一个换行符就做一次决策，下一行用选出的深度。答案取输出中最后一个数。

比较的策略有四组：E 的三个种子、R 的三个种子，以及冻结模型的纯深度 8 和纯深度 16。报告正确率、真实相对成本和配对差的区间，不作主结论。

### 6.5 时间

报告每个策略在 A10 上的生成墙钟时间和每 token 时间。`latest-m4` 的缓存查找在 Huginn 参考实现中以 Python 循环完成，计时反映的是参考实现的开销，本协议不设速度门槛。

### 7.3 KV 代价估计

在先导训练集的 128 篇上，每篇做两次真实执行，每个 chunk 的深度从五个候选中均匀随机抽取。令 $\Delta$ 为 chunk 深度与此前最大深度之差，按 $\Delta$ 所在的档位求实跑 NLL 减查表 NLL 的逐 token 平均值。档位为：

- $\Delta\le0$；
- 深一档，例如 6 对 4；
- 深两档；
- 深三档及以上。

$\Delta\le0$ 一档的均值作为基准，其余档位减去基准后即为 $\kappa$。估计值写入配置后固定，正式实验不再修改。

## 9. 统计检验

### 9.1 主检验

对确认文档 $i$，先对三个种子分别计算真实执行的 $\ell_{R,s,i}$ 与 $\ell_{E,s,i}$，再取平均：

$$
g_i=\frac13\sum_{s}\big(\ell_{R,s,i}-\ell_{E,s,i}\big).
$$

检验以文档为单位做配对 bootstrap，10,000 次，单侧，$\alpha=0.05$，备择为均值大于零。主结论要求同时满足四条：

1. 第 6.2 节的同成本条件成立。
2. 主检验显著。
3. 点估计不低于 0.005 nat/token。
4. 三个种子各自的平均效应均为正。零假设下三个种子同向的概率为 1/8。

结论的推断对象是这三个训练实例在同分布新题上的平均表现，每个种子的结果同时报告。

### 9.2 确认集规模

正式筛选集 745 篇只用于估计 $g_i$ 的标准差 $\hat\sigma$，计划标准差取 $\sigma=1.2\hat\sigma$。规划效应 $\delta=0.01$，最小实用点估计 $\delta_{\min}=0.005$，功效 0.8，单侧 $\alpha=0.05$：

$$
n\ge\max\left\{\left[\frac{(z_{0.95}+z_{0.8})\sigma}{\delta}\right]^2,\ \left[\frac{z_{0.8}\,\sigma}{\delta-\delta_{\min}}\right]^2\right\},\qquad
z_{0.95}=1.644854,\ z_{0.8}=0.841621.
$$

结果上取到 128 的倍数，最少 512，最多 1,310。

用第 2.5 节的数据预估：逐题差的标准差为 0.080，$\sigma=0.096$，两项分别约需 571 篇和 262 篇，上取到 640 篇。所需样本超过 1,310 时，运行全部 1,310 篇并报告功效不足，不把不显著解释为效应不存在。

### 9.3 次问题与次要指标

- **次问题。** J 与 E 都只取种子 17，报告 $\ell_{E,17,i}-\ell_{J,17,i}$ 的双侧 95% 区间和可检出效应。
- **次要指标。** 生成正确率报告 E 与 R 的配对差及其 bootstrap 区间，作为描述性结果。

## 10. 结果与研究决策

| 结果 | 支持的判断 | 后续工作 |
|---|---|---|
| 主结论成立 | 联合训练的共享末端在位置日程之外读出了与内容相关的深度信号 | 扩大到更长的推理和 ARC 一类带候选的任务 |
| E 优于静态混合但不优于 R | 收益来自位置结构，联合训练没有带来额外信号 | 检查文本候选形式的 Jev 读出或更强的控制器 |
| 真实执行显著差于查表 | KV 复用代价主导结果 | 研究补算历史 KV 或限制深度跃升的执行语义 |
| 区间较宽或成本不匹配 | 本研究不能完成对应判断 | 报告区间与成本，另立后续协议 |
| 生成正确率与 NLL 结论方向相反 | NLL 不足以代表推理质量 | 以生成正确率为主指标另立协议 |
